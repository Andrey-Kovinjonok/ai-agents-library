# Изменение библиотеки

## Перед изменением

1. Опишите владельца новых данных и границу между библиотекой и вызывающим
   продуктом.
2. Сформулируйте небольшой проверяемый сценарий. Исправление ошибки начинайте
   с теста, который воспроизводит ошибку.
3. Общий механизм переносите сюда только тогда, когда его одинаково используют
   как минимум два агентских продукта.

## Локальная проверка

Для текущего пакета достаточно Node.js 20 или новее. Внешних зависимостей нет,
поэтому устанавливать их перед тестами не требуется:

```sh
npm test
npm pack --dry-run --json
```

Первая команда запускает тесты. Вторая показывает файлы будущего пакета, но не
создаёт архив.

Проверки обязаны работать только во временных папках: не записывать данные в
настоящий домашний каталог, рабочие проекты, GitNexus или CodeGraph.

## Ограничения

- Не добавляйте сторонние зависимости без отдельного согласования.
- Не переносите в библиотеку предметную логику индексов и веток продуктов.
- Не добавляйте автоматическое удаление старых данных.
- Не публикуйте `.ai-design`: это локальный рабочий журнал, который может
  содержать абсолютные пути машины.
