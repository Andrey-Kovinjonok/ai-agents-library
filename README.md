# ai-agents-library

Общая библиотека на Node.js для наших локальных агентских инструментов. Это не
«библиотека путей»: `project-locations` — лишь первый переиспользуемый модуль.
Следующие общие возможности должны добавляться отдельными модулями, если они не
принадлежат одному конкретному продукту.

## Модуль расположения данных проекта

Модуль даёт GitNexus, CodeGraph и будущим продуктам единый способ:

- определить один канонический проект для основной копии Git, дополнительной
  рабочей папки Git и символических ссылок;
- построить читаемый псевдоним проекта;
- найти отдельную папку и отдельный `config.json` конкретного продукта;
- безопасно создать связь между реальным путём и папкой продукта;
- перечитать настройку при каждом вызове без перезапуска уже работающих агентов.

Например, путь:

```text
/Users/andreykovinenok/WORK/OF/frontend
```

даёт псевдоним:

```text
frontend_of_work_andreykovinenok
```

GitNexus и CodeGraph используют одинаковый псевдоним, но никогда не смешивают
свои данные:

```text
~/.agents/skills/
├── git-nexus/
│   ├── config.json
│   └── projects/
│       └── frontend_of_work_andreykovinenok/
└── codegraph/
    ├── config.json
    └── projects/
        └── frontend_of_work_andreykovinenok/
```

У каждого продукта собственный файл настройки. Общего списка проектов между
продуктами нет. Минимальная общая часть файла выглядит так:

```json
{
  "schemaVersion": 1,
  "projects": {
    "/Users/andreykovinenok/WORK/OF/frontend": {
      "directory": "projects/frontend_of_work_andreykovinenok"
    }
  }
}
```

Продукт вправе хранить рядом собственные поля. Например, он может перечислить
старые места и пометить их правилом `ask` — «перед очисткой спросить
пользователя». Библиотека сохраняет незнакомые поля без изменений, но сама
ничего из старых мест не удаляет и не предоставляет команду удаления.

## Использование

```js
import {
  ensureProductProject,
  resolveProductProject,
} from "ai-agents-library";

const prepared = await ensureProductProject("git-nexus", process.cwd());
console.log(prepared.projectDirectory);

// В каждом вызове config.json читается с диска заново.
const current = resolveProductProject("git-nexus", process.cwd());
console.log(current.mapping);
```

`ensureProductProject` — единственная операция первого модуля, которая создаёт
данные. Она пишет только под переданным корнем `.agents`, блокирует выход через
символическую ссылку и сериализует одновременные изменения `config.json`.

## Общий выбор веток для индексации

Модуль `branch-targets` обрабатывает продуктовый список целей:

```json
{
  "targetsVersion": 2,
  "targets": ["__CURERNT__", "origin/beta"]
}
```

`__CURERNT__` — точное специальное обозначение текущей выбранной ветки.
`current`, `Current` и `CURRENT` являются обычными именами настоящих веток.
Реальная ветка с именем `__CURERNT__` задаётся полной ссылкой
`refs/heads/__CURERNT__`. Указатель разрешается в настоящее имя при каждом вызове.

Библиотека не запускает Git и индексаторы, не пишет конфиги и не удаляет индексы.
Продукт передаёт свежие сведения о своей рабочей папке и получает конкретные
локальные/удалённые ветки без повторов. Старый формат требует явного перехода.

[Формат и примеры](docs/branch-targets.md).
[Проверка подключений трёх инструментов](docs/tool-integration-audit-2026-09-06.md).
Модуль готов в библиотеке; подключение внутри наших трёх инструментов ещё не выполнено.

## Навык `approval-continuation`

`approval-continuation` — первый потребитель общих функций библиотеки. Его
реализация на Node.js:

- перечитывает настройки при каждом событии без перезапуска агентов;
- подтверждает только два структурно проверяемых класса команд и никогда не
  разрешает произвольный `npm test` по одному названию;
- хранит наблюдения в отдельной папке продукта с читаемым псевдонимом проекта;
- не пишет служебные файлы в рабочий проект;
- устанавливает один канонический навык и символические ссылки для выбранных
  агентов, сохраняя чужие настройки и проектовые данные.

Код подготовлен, но сам навык не устанавливается автоматически. Формат данных,
список исполняемых сценариев, команда для отдельной установки и порядок
диагностики описаны в
[docs/approval-continuation.md](docs/approval-continuation.md).

## Границы ответственности

- Библиотека владеет общими функциями, типами и проверками безопасности.
- Каждый продукт владеет своим `config.json` и содержимым папок проектов.
- Наши ветки GitNexus и CodeGraph владеют индексами, ветками, копированием
  базового индекса и его достраиванием.
- Рабочий проект передаётся только как входной путь. Библиотека не создаёт в нём
  `AGENTS.md`, `CLAUDE.md`, `.agents`, `.claude`, планы или индексы.
- AI-POOL не участвует в этой интеграции.
- Стандартные сторонние ветки GitNexus и CodeGraph не должны подключать эту
  библиотеку; подключение предназначено только для наших веток.

## Проверка

Сторонних зависимостей у пакета нет. Достаточно установленного Node.js 20 или
новее:

```sh
npm test
```

Проверки используют только временные папки и не записывают данные в реальный
домашний каталог пользователя. `npm test` не устанавливает зависимости.

## Репозиторий и подключение

Пакет рассчитан на подключение из нашего Git-репозитория по неизменяемой метке
выпуска, начиная с `v0.0.1`. Это даёт GitNexus, CodeGraph и другим агентским
продуктам одну воспроизводимую версию библиотеки без привязки к локальному пути
машины.

Репозиторий:

```text
https://github.com/Andrey-Kovinjonok/ai-agents-library-
```

Клонирование:

```sh
git clone https://github.com/Andrey-Kovinjonok/ai-agents-library-.git
```

Пошаговое создание удалённого репозитория, первое отправление и формат
зависимости описаны в [docs/git-repository-setup.md](docs/git-repository-setup.md).
Локальная `.ai-design` не публикуется: она содержит рабочий журнал и абсолютные
пути среды.
