# `approval-continuation` на Node.js

`approval-continuation` — общий навык и сценарий-перехватчик событий агента.
Он решает три отдельные задачи:

- подтверждает только узкие заранее разрешённые классы безопасных команд;
- просит агента продолжить, когда тот явно сообщил о незавершённой работе и не
  ждёт решения пользователя;
- сохраняет обезличенную форму неудачной и затем успешной команды проверки как
  подсказку для следующих сеансов.

Это первый реальный потребитель `ai-agents-library`. Для определения проекта и
каталога данных он вызывает общий модуль `project-locations`, поэтому не имеет
собственного алгоритма хеширования путей.

## Состояние поставки

Исходный код и автоматические проверки находятся в этом репозитории. Сам навык
не устанавливается автоматически при клонировании, тестировании или
подключении пакета как зависимости. Установка в настоящий домашний каталог —
отдельное действие пользователя.

Исполняемые сценарии поставки:

- `bin/approval-continuation-hook.js` — принимает одно событие в формате JSON
  (`JavaScript Object Notation` — текстовый формат структурированных данных)
  через стандартный ввод и возвращает решение через стандартный вывод;
- `bin/install-approval-continuation.js` — создаёт канонический навык,
  символические ссылки выбранных агентов и точечно дополняет настройку событий
  Codex.

Автоматический адаптер событий сейчас реализован только для Codex. Остальные
шесть поддерживаемых агентов получают тот же `SKILL.md` через символическую
ссылку, но их собственные форматы событий потребуют отдельных адаптеров перед
включением автоматических решений.

Сторонних зависимостей нет. Нужен Node.js 20 или новее.

## Данные и владельцы

```text
~/.agents/skills/approval-continuation/
├── SKILL.md
├── agents/
│   └── openai.yaml
├── scripts/
│   └── acp-hook.js -> <ai-agents-library>/bin/approval-continuation-hook.js
├── config.json
└── projects/
    └── frontend_of_work_andreykovinenok/
        └── observations.json
```

- `config.json` принадлежит пользователю и навыку. Он содержит общую связь
  канонического пути с читаемой папкой, а также настройки политики.
- `projects/<alias>/observations.json` принадлежит одному проекту. `alias`
  (читаемый псевдоним пути) строится общей библиотекой.
- `scripts/acp-hook.js` является символической ссылкой на исполняемый файл
  конкретной копии пакета. Если копию репозитория перенесли, установщик нужно
  повторить из нового места; `config.json` и `projects/` при этом сохраняются.
- Каталоги конкретных редакторов содержат ссылки на один канонический навык, а
  не отдельные копии.

Минимальная форма настройки:

```json
{
  "schemaVersion": 1,
  "projects": {},
  "settings": {
    "trustedWorkRoots": [
      "/Users/example/WORK/OF",
      "/Users/example/WORK/GITHUB"
    ],
    "approval": {
      "enabledClasses": [
        "node-check",
        "localhost-headless-screenshot"
      ]
    },
    "continuation": { "enabled": true },
    "observations": { "enabled": true },
    "safety": { "enabled": false }
  },
  "legacyLocations": []
}
```

Настройки читаются с диска при каждом событии. Для изменения `config.json`
перезапуск уже работающих агентов не нужен. Текст `SKILL.md` среда агента может
хранить в памяти до конца сеанса, поэтому только изменение текста навыка иногда
требует нового сеанса.

`legacyLocations` (список старых мест) носит информационный характер. Каждая
запись имеет `cleanupPolicy: "ask"`, то есть перед очисткой нужно отдельно
спросить пользователя. У библиотеки нет операции автоматического удаления.
В начальный список входят старый общий конфиг, старое хранилище наблюдений,
каталог `.codex/acp` из исходного архива и прежний Python-сценарий внутри
канонического навыка.

## Политика подтверждений

Поддерживаются только два класса:

- `node-check` — ровно `node --check <относительный-файл>`, без перехода к
  родительскому каталогу и без файла окружения;
- `localhost-headless-screenshot` — ограниченный запуск Chromium или Chrome в
  фоновом режиме только для адреса `http://localhost` либо
  `http://127.0.0.1`, с выводом изображения только во временную папку.

Название `npm test` само по себе ничего не разрешает. Неизвестное событие не
получает автоматического решения и остаётся штатному механизму подтверждения
агента.

## Установка после отдельного решения пользователя

Следующая команда изменяет домашние настройки. Её не нужно выполнять для
проверки исходного кода:

```sh
node bin/install-approval-continuation.js \
  --agent all \
  --trusted-root /Users/example/WORK/OF \
  --trusted-root /Users/example/WORK/GITHUB
```

Для безопасной предварительной проверки можно указать полностью изолированный
дом:

```sh
node bin/install-approval-continuation.js \
  --user-home /tmp/approval-continuation-home \
  --agent codex \
  --agent claude
```

Установщик выполняет полную проверку конфликтов до первой записи. Он
останавливается, если каноническая папка принадлежит другому навыку, путь
конкретного агента не является ожидаемой символической ссылкой либо файл
`hooks.json` Codex имеет несовместимую структуру. Чужие файлы не удаляются и не
заменяются.

Повторный запуск обновляет только поставляемые файлы `SKILL.md`,
`agents/openai.yaml`, ссылку на исполняемый сценарий и принадлежащие навыку
записи событий Codex. Проектовые записи, неизвестные поля настройки и чужие
события Codex сохраняются.

## Проверка и диагностика

```sh
npm test
node --check bin/approval-continuation-hook.js
node --check bin/install-approval-continuation.js
npm pack --dry-run --json
```

`npm test` здесь только запускает встроенный тестовый сценарий пакета и ничего
не устанавливает. Проверки создают изолированные временные дома и не обращаются
к настоящему `~/.agents`.

Если события не срабатывают после будущей установки, проверить по порядку:

1. существует ли `~/.agents/skills/approval-continuation/config.json`;
2. ведёт ли `scripts/acp-hook.js` к существующему файлу библиотеки;
3. присутствует ли ровно одна запись навыка для нужного события в
   `~/.codex/hooks.json`;
4. входит ли рабочая папка в `settings.trustedWorkRoots`;
5. включён ли соответствующий раздел настройки.

После изменения только `config.json` перезапускать сервер или агентов не нужно.
После переноса библиотеки повторно запускается установщик. После изменения
текста `SKILL.md` новый сеанс может понадобиться из-за памяти среды агента.
