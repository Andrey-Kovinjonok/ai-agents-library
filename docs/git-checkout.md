# Общие операции с исходной рабочей папкой

`ai-agents-library/git-checkout` — технические функции для нескольких продуктов.
Они не управляют индексами и не создают общего списка проектов.

- `readGitCheckout(path)` возвращает фактический корень рабочей папки, имя ветки
  или null, полный номер текущего коммита и названия удалённых источников.
- `branchDirectoryName(branchKey)` создаёт безопасное имя каталога ветки.
  Читаемая часть дополнена контрольным кодом полного ключа: `feature/x`,
  `feature-x` и `Feature/x` не смешиваются. Это правило для веток; имя папки
  проекта по-прежнему читаемое обратное имя полного пути, без контрольного кода.
- `createGitSourceSnapshot(options)` создаёт независимый внешний снимок.
  `workingTree:true` берёт текущие обычные файлы, иначе — файлы заданного коммита.
  Исходный репозиторий, включая его служебную папку Git, не изменяется.
  `previousSnapshot` допускает продолжение технической истории ранее созданного
  этой функцией снимка того же источника. Выбор базового индекса делает продукт.

Файлы окружения `.env*` и `*.env`, символические ссылки, подмодули и служебные
каталоги исключаются до чтения содержимого. Список исключённых имён возвращается
в `excluded`. Отдельный файл больше 32 MiB или сумма больше 512 MiB вызывают
ошибку, а не молчаливое неполное копирование. Это пока фиксированные ограничения.

Результат содержит `sourceCommit` — настоящий пользовательский коммит,
`sourceFingerprint` — контрольную сумму скопированного содержимого,
`snapshotCommit` — коммит отдельной технической истории. Последние два значения
не заменяют настоящий коммит и не доказывают отсутствие новых правок после снимка.

`reuse:true` обновляет прежний снимок на месте. В `destination` передают
`directory` из результата его создания. Снимок другого исходного проекта
отклоняется. Изменённые и добавленные файлы записываются, отсутствующие удаляются
только из снимка; права исполнения приводятся к исходным. `changedFiles` сообщает
число изменённых файлов. При отсутствии изменений файлы не переписываются и
новый коммит не создаётся. До изменения снимка проверяются компоненты его путей:
символические ссылки, включая висячие, отклоняются. Одновременное враждебное
изменение дерева сторонним процессом полностью не изолировано этим механизмом.

`updateProductProject(product, path, patch, options)` дополняет запись в собственном
конфиге продукта под блокировкой и сохраняет остальные поля и проекты.
Поле размещения `directory` этим вызовом менять нельзя. Чтение настроек не кешируется.

## Состояние подключения

В наших GitNexus и CodeGraph добавлены `agent/cli.mjs` и `agent/engine.mjs`.
Они используют эти функции, общий выбор `targets` и отдельные конфиги продуктов.
Это ещё не перенос установленных обработчиков агентов: старые места запуска
не переключены, настройки прежнего общего обработчика не мигрированы.
Graphify ожидает создания нашей ветки и следующего этапа подключения.
